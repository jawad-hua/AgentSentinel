## Evidence provenance

Testing used a newly installed, isolated n8n instance, not the user's n8n. One temporary
workflow derived from AgentSentinel_Master.json was executed for real. The test harness
changed only this dedicated test workflow and used a real local HTTP service to produce
success, 503, empty output, invalid JSON field, timeout and delayed responses. These were
actual n8n node executions, not mocked n8n API responses or inserted incident fixtures.
The AgentSentinel application used a read-scoped API key and its actual polling pipeline.

Final run workflow ID: `gBHjpNUBXPuV5p2f`. Execution IDs 1–83 were generated by n8n. Five
incident categories were observed: HTTP failure, invalid JSON, empty output, timeout and
abnormal latency. The isolated test database, workflow credentials, raw traces and test
service are not part of the patch. The user's existing database is not replaced or seeded.

The timeout test exposed a compatibility detail: n8n can put the explicit timeout reason
in `error.messages` while the top-level message only says the connection was aborted.
The detector now examines those actual fields in memory and retains only the safe
category. A regression test uses the non-sensitive fields of that observed error shape.

## Scope and limitations

This patch has been validated on Linux with n8n 2.15.1, not on the user's Windows laptop.
The user's existing Windows foundation was already verified; this incremental migration,
new build and actual monitored execution still need their acceptance check.

No Groq inference, AI diagnosis, confidence score, repair, approval, rollback, replay or
Chaos Mode capability is claimed. Generic node/parser categorization is implemented;
not every provider-specific error format has been exercised. JSON contracts check object/
array syntax/type, not arbitrary JSON Schema. Monitoring cannot recover unsaved/pruned
n8n traces. One process and one n8n instance per database are supported.

The Starlette test-client httpx deprecation warning remains; no warnings were suppressed.
The previously observed braces/ESLint development dependency advisory is unresolved. No
frontend dependencies were changed, downgraded, forcibly updated or hidden from audit.
The user's earlier `npm audit --omit=dev` returned zero; a current audit can be rerun at
release time. This is still a local-only operator console with production auth/deployment
hardening scheduled for Phase 6.

Phase 2 implementation is ready for user acceptance. Do not begin Phase 3 until confirmed.
